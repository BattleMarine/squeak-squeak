## 2. 다음 구현: S3-03a 저장 데이터와 안전한 저장소

Ra의 권장 방향에 따라 **현재 완성 결과의 최소 영구 저장·복원을 S3-03에 포함**한다. 일반 진행은 책임을 분리하되 미채택 경제를 저장하기 위해 새로 구현하지 않는다. `ExperimentSnapshot`을 출발점으로 사용하고 메모리 객체를 직접 직렬화하는 대신 검증 가능한 저장 DTO를 둔다.

- **완성 결과:** 결과 ID·형식 버전, 동전/반응/배치 ID 및 정의 버전, 해상도·완료 시간·초기 오염 기준, A 상태·양면 B/광택/풀림을 보존한다. 고정 배치를 임의 시드로 대체하지 않는다. 정의 변경으로 옛 결과 외형이 달라지는 문제는 버전 검증/호환 정책으로 다룬다.
- **일반 진행:** 별도 버전/저장 책임. 기존 정의의 도구 소유·해금 제약은 유지한다. 실험용 전체 도구 접근을 소유권으로 기록하거나 미채택 재화/가격/등급/보상을 생성하지 않는다.
- **제외:** 현재 청소 중인 판, 카메라 자세, 임시 입력/대화상자 상태는 앱 종료 후 복원하지 않는다. 기존 보관 결과의 열람/표면 복원과 미완료 판 재개를 혼동하지 않는다.
- **용량:** 현재 상한16개를 우선 유지한다. JSON/압축 payload 후보의 실제 크기·오차·로드 비용을 비교하고 제한을 명시한다. 해시는 식별/무결성 확인용이며 표면 데이터를 대신하지 않는다. 장기 수백 개·공유 형식 최적화는 별도다.
- **실패 계약:** 유효 사본 생성→임시 파일 쓰기/닫기→기존 유효본 백업/교체→메모리 성공 확정. 실패 시 기존 파일과 현재 작업 유지. 같은 결과 ID 재시도는 중복 보관하지 않는다. `persistentDataPath` 제품 저장과 임시 테스트 경로를 분리한다.
- **로드 검증:** 버전·ID/정의 버전·중복·배열 길이·수치 범위/유한성·양면/풀림 일관성·최대 개수/크기를 검증한다. 미래 버전·양쪽 손상은 자동 초기화/덮어쓰기하지 않는다. 유효 백업 복구와 오류 상태를 구분한다.

### 세부 진행 순서

1. **S3-03a:** DTO·결과/일반 진행 책임·형식/용량 비교·검증기·안전한 저장소·격리된 실패/왕복 검사. 직렬화 API를 선택하기 전에 현재 Unity 런타임 지원과 기존 구조를 확인한다.
2. **S3-03b:** 보관 확정에 저장소 연결, 실패/재시도/취소·종료/재실행, 저장된 완성 결과를 읽어 양면 상태와 외관을 복원·검증. 정식 전시실은 구현하지 않는다. 실패 시 저장 성공처럼 보관 상태로 전환하지 않는다.
3. **S3-04:** 동일 결과 ID로 최종 보관의 중복 확정·추가 청소·결과 열람을 통합 검증한다. 등급/보상은 보류한다.
4. **S3-05:** 상점/구매 신규 구현은 보류한다. 기존 모드의 잠금과 실험 도구 접근을 혼동하지 않는 회귀를 유지한다. 새 획득 방식은 별도 결정한다.
5. **S3-06~07:** 보관/오류/종료 안내와 저장 결과 열람을 통합하고 새 빌드 재실행 및 이월 항목을 검사한다. 정식 작업대 도구함/방 이동 구현은 별도다.

## 3. 인계 상태

Rc 범위 정리와 저장 구현의 시작 조건을 문서로 확정했다. S3-03a/b 코드·파일 저장·제품 연결은 **아직 미착수**다. 다음 구현 담당은 AGENTS/README/Step3 지시서 및 이 문서를 읽고 실제 Git/Unity 기준선부터 확인한다. 저장 구현 완료 전까지 현재 제품은 최대16개의 시험용 메모리 보관이며 종료 시 사라진다.
