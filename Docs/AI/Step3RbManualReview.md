# Rb 수동 테스트 반영·문지르기 속도 조사

2026-10-17 · 기준 커밋 `4a22ce3`. 원본: [사용자 테스트 기록](../Step3Rb-수동테스트_2610171034.md). 사용자는 Unity 에디터가 아닌 빌드된 exe로 테스트했다고 확인했다. 정확한 실행 파일 해시는 미수집이며 제공한 Rb 빌드 기준의 보고로 취급한다.

## 사용자 결과 판정

- 정상 보고: 실험 진입, 이동 중에만 청소, 재질 차이, 한 클릭 한 방울, 국소 풀림, 입력 차단, 양면 진행, 100% 이후 추가 청소, 보관 확인/취소, 다음 판, 포기/종료, 표현·소리, 기존 모드와 완료 연출 중 실험 진입.
- 스캐너는 체크됐지만 뒷면 A 외곽 원이 앞에서도 보였으므로 **부분 실패**다. 전체 통과로 집계하지 않는다.
- 보관 상한의 메모는 보관 후 버튼 비활성화에 관한 것이다. 중복 보관 차단은 확인됐지만 **16개 초과 거부의 수동 검증은 미확인**이다.
- 문지르기는 정지 차단은 정상이나 느린 이동이 빠른 이동보다 효율적으로 느껴졌고 트랙패드가 더 빠르다는 보고가 있다. 아래 원인 조사와 분리한다.
- MMB 회전을 동전 위에서만 시작하는 제약은 UI 밖 게임 화면 전체에서 시작하도록 개선 요청됐다.
- 약품 후 칫솔 B 제거는 설계대로다(M1 계수.25, M2 1). 기존 완료 연출 중 실험 진입은 연출 취소 후 새 실험 판으로 즉시 전환하는 현재 동작이다.

## Rc 해석

풀림/제거, 잔여 오염 확인, 100%/보관의 구분은 이해됐다고 보고했다. 완료 시간은 대략10분 안쪽이며 동전별 실측은 아니다. 회전 시작 위치가 번거로웠다. 도구 선택 이유와 계속 플레이하고 싶은지는 미기록이다. **부분 체험 완료·수정 후 재확인 대기**이며 Rc 전체 채택/재미 통과로 표시하지 않는다. 외부 비개발자 체험·성능 측정은 별도다.

## 문지르기 속도 — 코드 근거

현재 `CleaningRubMotion.Sample`은 이동량을 `min(이동거리 / 기준속도, 프레임 시간)`의 유효 청소 시간으로 바꾼다. CleaningRoom의 기준속도는0.6월드단위/초, 최소 누적거리는0.001이다. 가속도는 사용하지 않는다. 기준속도 이상에서는 더 빨리 움직여도 초당 처리 예산이 증가하지 않는다.

`CoinSurfaceBrushStroke.ApplyApprovedSweep`는 그 예산을 경로 표본 수로 나눈다. 각 B 텍셀의 가중치는 `(1 - 중심거리²/반경²)²`여서 중심에서 강하고 가장자리에서0이다. A도 경로 표본에 유효 시간을 분배한다. 따라서 빠른 긴 획은 같은 프레임 예산을 넓게 나누며 오염 위에 머무는 시간도 짧다. 유효 접촉 밖/면 전환/UI/회전/줌/F는 연속 접촉을 끊는다.

| 가설 | 현재 근거·판정 |
| --- | --- |
| 속도 상한+국소 체류가 빠른 획의 효율을 제한 | 코드와 실제 커널 통제 측정으로 확인. 한 획의 제거량 감소를 설명하며 동일시간 왕복에서는 상한 이상 결과가 거의 같음 |
| 트랙패드가 다른 청소 배율을 사용 | 청소 계산은 동일한 화면 포인터→월드 접촉 경로를 사용. 별도 배율 근거 없음 |
| 장치별 경로/이벤트 빈도·포커스·FPS 차이 | 실제 장치 궤적 미수집으로 미확정. 트랙패드 원인을 단정하지 않음 |

빠른 이동과 느린 이동의 비교는 **같은 경로1회**와 **같은 실제 시간의 왕복**을 구분해야 한다. 현 로직에서는 전자는 통과 시간이 달라지고 후자는 접촉 분포가 달라진다. 가속도 방식은 일정 속도 문지르기를 약하게 만들거나 방향 전환에 보상을 집중시킬 수 있어 즉시 도입하지 않는다. 속도 상한을 완만하게 높이거나 거리 기반 예산을 허용하는 변경은 통제 측정과 사용자 판단 이후 별도로 결정한다. 이번 요청에서는 청소 속도 로직·수치를 변경하지 않는다.

## 실제 커널 측정 결과

디벨로퍼의 `MeasureExistingSpeed()` 실행 결과와 검사 코드를 대조했다. 60Hz·실제 M1 미처리 천(반경.32/제거속도4.8/계수.5), 균일 B1/res128의 월드거리1 경로를 사용했다. 입력 장치를 흉내 낸 결과가 아니라 실제 청소 커널에 동일한 접촉 경로를 넣은 측정이다.

| 이동속도(world/s) | 같은 경로1회 유효 청소초 | 1회 앞면 전체 제거율 | 동일4초 왕복 앞면 제거율 |
| --- | --- | --- | --- |
| 0.3 | 1.666667 | 12.5053% | 13.9086% |
| 0.6 | 1.666665 | 12.5052% | 17.6152% |
| 1.2 | 0.833333 | 6.8140% | 17.4786% |
| 2.4 | 0.416667 | 3.4070% | 17.6028% |

**판정:** 기준속도 이상에서 같은 획1회의 효과가 약해지는 것은 현 시간 상한·경로 분배로 재현됐다. 동일시간 왕복에서는 .6~2.4의 전체 제거율이 거의 같고 .3은 더 낮았다. 따라서 “느릴수록 언제나 더 빠르게 완료”되는 역전 결함을 확인한 것은 아니다. 사용자 체감에는 오염 위 체류·유효 범위 이탈·중심 가중치가 함께 작용할 수 있다. 트랙패드 비교는 실제 두 장치의 동일 궤적/FPS/포커스 측정 없이는 확정할 수 없다. 정확한 표본·중심 제거량은 [개발 검증](Step3RbFollowupValidation.md) 참조.

권장 후속은 먼저 수정본을 체험하고, 빠른 문지르기에도 보상을 늘릴지 결정하는 것이다. 채택하면 현재 상한을 완만한 속도 곡선으로 조정하는 안을 비교하되, 가속도만으로 청소량을 정하는 방식부터 적용하지 않는다.
