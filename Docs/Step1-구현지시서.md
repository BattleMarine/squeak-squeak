# Step 1 구현 지시서 — 동전 하나의 청소 MVP

작성: 2026-09-16. 대상: 이 저장소에서 구현을 이어갈 AI. 상태: **구현 전 인계 문서**.

## 1. 수행 목표와 문서 사용법

`CleaningRoom`에서 **도구 선택 → 직접 청소 → 광택 → 완료 결과 → 다시 시작**을 구현하고 Windows 빌드에서 검증한다. 동전당 목표 시간은 3~5분이다.

- 먼저 [AGENTS](../AGENTS.md), [README](../README.md), 이 문서를 읽는다. 단계 범위는 [ROADMAP](../ROADMAP.md), 기존 씬·검증 근거는 [Step 0 기록](Step0-검증.md)을 참고한다.
- 아래 **확정 요구**는 사용자 결정과 기존 기획이다. **구현 기본안**은 이번 인계에서 정한 제안이며, 미지정 세부사항은 이 안으로 진행한다. 더 단순하고 동등한 방식을 택하면 이유와 차이를 보고한다.
- 계획 제시나 코드 생성에서 멈추지 말고 씬 부착·참조·UI 이벤트·저장·검증까지 수행한다. 도구 제약으로 못 한 작업은 명시한다.
- 본 문서는 구현 요청이며 커밋·push·PR·패키지 추가 승인까지 포함하지 않는다. 요청받은 작업 단위가 있으면 그 범위를 우선한다.

## 2. 출발 상태와 보존 대상

| 항목 | 확인된 기준 |
| --- | --- |
| 환경 | Unity 6000.3.23f1 / URP 17.3.0 / Input System 1.20.0 / Windows x64 |
| 화면 | 제품명 `Squeak Squeak`, 1280×720 창 모드, 창 크기 조절 불가 |
| 시작 씬 | `Assets/Scenes/CleaningRoom.unity`; `SampleScene`은 보존·빌드 제외 |
| 계층 | Main Camera, Directional Light, Workbench, Coin/CoinBody |
| 동전·카메라 | 임시 Cylinder와 Convex MeshCollider; Coin 위치 `(0, 0.13, 0)`, 카메라 `(0, 6, 0)`, 회전 `(90, 0, 0)`, Orthographic Size 2.4 |
| 구현 상태 | 입력·청소 런타임 코드 없음. Step 0 로컬 빌드 및 다른 PC Clone·빌드·실행 성공 |
| 입력 에셋 | `Assets/InputSystem_Actions.inputactions`에 템플릿 Player·UI 맵이 존재; 청소용 입력은 아직 없음 |

시작 시 Git 상태와 실제 에디터 연결·씬·저장 상태를 다시 확인한다. 문서 작성 당시 `ProjectSettings.asset`, `UnityConnectSettings.asset`에 기존 로컬 변경이 있었다. 이를 초기화하거나 작업에 무단 혼합하지 않는다. 기존 Instance ID는 재사용하지 않는다.

## 3. 확정 요구와 제외 범위

### 입력

| 입력 | 필수 동작 |
| --- | --- |
| Mouse Move | 청소 도구 커서 이동 |
| LMB Hold / Drag | 현재 도구 사용 |
| MMB Drag | 동전을 잡아 자유 회전 |
| Mouse Wheel | 확대·축소 |
| F | 동전 위치·회전·Zoom 초기화 |

- 회전 대상은 동전이며 카메라는 탑뷰를 유지한다. F는 청소 진행을 초기화하는 키가 아니다.
- 마른 천·작은 솔·광택천 3종을 선택할 수 있어야 한다. 기본안은 화면 버튼 3개이며 선택 상태를 표시한다.
- A 타입은 개별 오염 오브젝트, B 타입은 표면 오염 수치와 색상 변화로 구현한다. 광택은 별도 수치와 머티리얼 변화로 표현한다.
- 진행률을 표시하고, 결과에 청결도·광택도·완료 시간을 제공한다. 다시 시작하면 동일 조건의 새 청소가 가능해야 한다.

### 이번 단계에서 제외

여러 동전·스테이지, 랜덤 오염 생성, 상점·보상·해금, 저장·불러오기, 수집·전시, 표면 손상, 고급 셰이더·RenderTexture 마스크, 정교한 파티클·사운드 시스템. 임시 도형과 기존 패키지로 구현한다. 최소 커서·색상·광택 피드백은 포함한다.

## 4. 구현 기본안

### 4.1 입력과 표면 판정

- 새 Input System의 청소용 Action Map을 구성한다. 기존 UI 맵·GUID를 보존하며 UI와 게임 입력을 구분한다. Action 이름·파일 구성은 구현자가 정한다.
- 카메라 Raycast로 동전의 현재 보이는 표면 위치·법선·로컬 좌표·적중 여부를 구한다. 회전 전 고정 평면만으로 판정하지 않는다.
- 동전에 적중하면 커서를 표면에 표시하고, 벗어나면 비활성 표시 또는 숨김 처리한다. 커서 자체가 Raycast를 막지 않도록 한다.
- LMB를 누른 동안 유효한 접촉에 시간 기반 효과를 적용한다. 정지한 채 Hold해도 사용 가능하며 프레임 수로 제거량을 계산하지 않는다.
- **MMB 회전 중에는 청소를 중지**한다. UI 위에서 청소·회전을 시작하지 않고, UI 위 스크롤은 줌에 전달하지 않는다. 포커스를 잃으면 눌림·드래그 상태를 해제한다.
- MMB는 동전에 적중한 상태에서 시작한다. 드래그 중 포인터가 동전을 벗어나도 버튼을 놓을 때까지 회전을 유지한다. 이동량을 카메라 기준 두 축의 회전에 반영한다.
- 회전한 동전·오염이 작업대에 묻히지 않도록 초기 동전 높이를 필요한 만큼 조정할 수 있다. 조정 후 화면 구도와 F 복원 기준을 기록한다. 오염은 Coin의 로컬 좌표로 함께 회전한다.
- 줌은 Orthographic Size를 변경하고 최소·최대값으로 제한한다. 감도·범위는 Inspector에 노출한다. F는 씬 초기화 후 저장한 동전 Transform과 카메라 Size를 복원한다.

### 4.2 오염·도구·광택

- A 오염은 재현 가능한 고정 배치로 시작한다. 각 오염의 내구도를 접촉 중 감소시키고 0이면 제거한다. 크기 감소 등 최소 반응을 보여준다.
- 브러시 범위 안의 **보이는 오염**만 영향을 받게 한다. 반대편·작업대 뒤 오염을 거리만으로 지우지 않는다. 회전해도 청소 가능한 배치를 사용한다.
- B 오염은 동전 전체의 단일 수치로 충분하다. 동전 접촉 중 감소시키고 전체 표면 색상으로 반영한다. 위치별 닦인 자국은 Step 2 과제다.
- 광택은 URP Lit의 Smoothness 등으로 표현한다. B 색상과 광택 값이 서로 덮어써지지 않아야 한다. 공유 머티리얼 원본에 런타임 값을 저장하지 않는다.
- 도구별 반경·A 제거력·B 제거력·광택 상승량을 직렬화 필드 또는 작은 데이터 에셋으로 노출한다. 다음 상대적 역할을 지킨다.

| 도구 | A 제거 | B 제거 | 광택 |
| --- | --- | --- | --- |
| 마른 천 | 보통 | 기본 표면 청소에 적합 | 낮음 |
| 작은 솔 | 가장 강함 | 낮음 | 없음 |
| 광택천 | 낮음 | 낮음~보통 | 가장 강함; 오염이 많으면 효율 감소 |

정확한 제거 속도는 플레이 시간에 맞춰 조정한다. 한 도구가 모든 역할에서 최선이 되지 않도록 한다. 3~5분을 맞추기 위한 강제 대기 시간은 넣지 않는다.

### 4.3 수치·완료·재시작

아래는 초기 계산 기본안이다. 분모와 초기값은 매 판 시작에 고정한다.

- A 제거율 = 제거된 개수 / 초기 개수. 초기 개수 0이면 100%로 처리한다.
- B 제거율 = `1 - 현재 오염량 / 초기 오염량`. 초기 오염량 0이면 100%로 처리한다.
- 청결도 = A·B 제거율의 평균. 광택도는 별도 0~100% 값이다. 표시·판정 값은 유효 범위로 제한한다.
- 초기 완료 기준은 **A ≥ 90%, B ≥ 80%, 광택 ≥ 70% 모두 충족**이다. 기획 예시에서 가져온 조정 가능한 기본값이며 Inspector에 노출한다. 평균 청결도만으로 완료시키지 않는다.
- `Cleaning → Completed` 전환은 한 번만 발생한다. 결과 표시 후 청소·회전·줌 입력과 타이머를 멈춘다.
- 시간은 첫 유효 청소부터 완료까지 측정하고, 앱 포커스를 잃은 시간은 제외하는 것을 기본안으로 한다.
- 다시 시작하면 A 오염·B 오염·광택·시간·완료 플래그·결과 UI·입력 상태를 모두 복원하고, 기본 도구인 마른 천과 초기 자세·줌으로 돌아간다. F는 이 중 자세·줌만 복원한다.

## 5. 구조와 씬 연결

입력, 표면 판정·자세 제어, 도구 데이터, A/B·광택 상태, 완료·재시작, UI의 책임을 구분한다. 아래는 배치 기준이며 클래스 이름·개수를 강제하지 않는다.

| 대상 | 연결할 책임 |
| --- | --- |
| Coin / CoinBody | 오염·광택 상태, Collider, Renderer, 회전 대상 |
| Coin 하위 오염 그룹 | 고정 A 오염 목록과 초기 상태 |
| ToolCursor | 현재 표면 위치·도구 반경·사용 가능 여부 표시 |
| 씬 제어 오브젝트 | Input Actions, Camera·Coin·커서 참조, 도구 선택, 완료·재시작 |
| Canvas / EventSystem | 도구 버튼, A/B 제거율·광택 HUD, 결과·재시작; Input System 대응 UI 입력 |

필요한 런타임 코드는 `Assets/Scripts/`, 에디터 도구는 `Assets/Editor/` 아래에 둔다. 작은 프로토타입에 범용 이벤트 버스·서비스 프레임워크를 도입하지 않는다. 매 프레임 이름 검색으로 참조를 찾지 말고 Inspector 참조를 연결한다. 기존 씬을 통째로 재생성하지 않는다.

## 6. 작업 단위와 통과 기준

한 단위씩 구현·저장·검증하고 진행한다. 중단 시 마지막 완료 단위와 다음 작업을 기록한다.

| 순서 | 작업 | 통과 기준 |
| --- | --- | --- |
| S1-01 | 입력·표면 판정·커서·MMB·Wheel·F | 회전·줌 후에도 커서 적중 정상, UI 입력 분리, F 자세 복원 |
| S1-02 | 도구 3종·선택 UI | 선택 상태와 도구 데이터 일치, 버튼 클릭이 청소로 전달되지 않음 |
| S1-03 | 고정 A 오염·제거 | 접촉한 오염만 감소·제거, 회전 시 부착 유지, 제거율 일치 |
| S1-04 | B 제거·색상·광택 | 유효 접촉에서만 변화, 도구 차이와 청소 전후 변화 확인 |

| S1-06 | 튜닝·Windows 빌드·문서 | 전체 루프 실행 검증, 소요 시간 기록, 필수 검사 결과와 빌드 경로 인계 |

## 7. 검증 체크리스트

결과는 통과 / 실패 / 미실행으로 기록한다. 실패·미실행을 숨기거나 완료로 표시하지 않는다.

- [ ] Unity 컴파일·임포트 완료, 새 Console 오류 없음, Missing Script·필수 참조 누락 없음.
- [ ] 동전 밖·UI 위에서는 청소되지 않으며 MMB+LMB 동시 입력 시 회전만 작동한다. 포커스 복귀 후 도구가 혼자 작동하지 않는다.
- [ ] 동전 회전·줌 극값에서 표면 판정과 오염 위치 정상. 뒤쪽 오염이 관통 제거되지 않는다.
- [ ] F는 자세·줌만 복원하고 청소 진행을 보존한다.
- [ ] 도구별 차이 확인, B 색상과 광택이 함께 유지되며 Play Mode 종료 후 원본 머티리얼 값이 오염되지 않는다.
- [ ] 완료 조건 경계값, 초기 오염 0, 범위 초과 방지, 완료 1회 발생을 검증한다. 순수 수치 로직은 가능한 경우 작은 EditMode 테스트로 확인한다.
- [ ] 완료 → 결과 → 재시작 → 재완료를 최소 2회 반복하고 이벤트 중복·누적 오염·남은 결과 UI가 없는지 확인한다.
- [ ] 대표 플레이 1회의 실제 소요 시간을 기록한다. 3~5분 범위 밖이면 원인과 조정 값을 남긴다.
- [ ] Windows x64 빌드에서 선택·청소·회전·줌·F·결과·재시작을 실제 입력으로 확인한다. 숨김 실행·로그 확인만으로 입력 검증을 대체하지 않는다.
- [ ] 1280×720 UI 가독성과 창 크기 조절 불가·제품명을 확인한다. 빌드는 `Builds/Windows/Step1/` 등 제외 경로에 출력하며 기존 결과를 무단 덮어쓰지 않는다.

기존 빌드에는 AI Inference 패키지 셰이더 경고 485건과 Player의 D3D12 info queue 메시지가 있었다. 시작 시 새 기준 로그를 기록하고 새 오류와 구분한다. 경고 제거를 위해 패키지·그래픽 설정을 임의로 바꾸지 않는다.

## 8. 완료 보고와 후속 인계

README에는 현재 동작·실행 방법을, ROADMAP에는 진행 상태를 갱신한다. `Docs/Step1-구현결과.md`에 아래 내용을 간결하게 남긴다. Step 0 기록은 과거 검증 근거로 보존한다.

```text
상태: 완료 / 부분 완료 / 차단
완료 작업: S1-01~06 각각의 상태
변경 파일·씬 연결: 오브젝트 → 컴포넌트 → 필수 참조
선택한 기본안·변경 이유: 계산식, 도구 수치, 입력 우선순위, 초기 자세·줌
검증: 환경, 재현 순서, 기대/실제 결과, Console, 플레이 시간
빌드: 경로, 성공 여부, 오류·경고, 실제 입력 검사 여부
남은 작업: 실패·미실행 항목과 다음 수행 순서
```

Step 1 완료는 코드 수가 아니라 **빌드에서 검증된 한 판의 청소·결과·재시작 루프**로 판단한다. 완료 후 Step 2 구현은 별도 요청을 기다린다.
