- 먼저 [AGENTS](../AGENTS.md), [README](../README.md), [ROADMAP](../ROADMAP.md), 이 문서를 읽는다. 세부 진행은 [Step 2 체크리스트](AI/Step2ImplementationChecklist.md)에만 기록한다.
- **사용자 결정:** Step 1의 `s1-06-f2` 실제 플레이 검증을 보류하고 Step 2를 먼저 진행한다. Step 1을 완료로 바꾸거나 과거 미검증을 통과로 바꾸지 않는다. Step 2 첫 실행 가능한 빌드부터 이 항목을 함께 검증한다.
- 아래 **유지 요구**는 기존 결정이며 **구현 기본안**은 이번 인계의 제안이다. 동등하고 더 단순한 대안을 선택하면 이유·범위·검증법을 먼저 기록하고 진행한다.
- 한 작업 단위씩 코드·씬 연결·저장·검증까지 마친다. 도구 제약이나 외부 테스트 대기는 명시하고 독립 작업을 계속한다. 이 문서는 커밋·push·패키지 추가·유료 에셋 구매 승인까지 포함하지 않는다.

## 3. 구현 기본안

### 3.1 표면 좌표와 청소 대상

- 먼저 한 지점의 접촉을 동전 로컬 좌표로 변환하고, 회전·줌 후에도 같은 자리를 가리키는 작은 실험을 한다. 입력 적중·시각 표시·마스크 갱신은 같은 좌표 변환을 사용한다.
- 기본 범위는 **앞면·뒷면을 별도 청소 영역으로**, 옆면은 외형 전용으로 둔다. 옆면은 B/광택 집계에서 제외하고 그 위의 B/광택 사용 불가를 커서에 표시한다. 접촉 한 번으로 반대편을 닦지 않는다.
- 기존 임시 Cylinder의 UV·Convex Collider가 필요한 좌표를 제공한다고 가정하지 않는다. 기본안은 동전 로컬 평면 좌표와 면 법선으로 앞뒷면을 구분하는 방식이다. UV를 사용한다면 겹침·이음새와 렌더 Mesh/Collider 일치를 먼저 검증한다.
- 브러시 크기는 기존 월드 반경과 일치시킨다. CoinBody의 비균일 스케일을 고려하고 화면 픽셀 반경으로 제거하지 않는다. 면 경계에서 브러시가 다른 면·옆면으로 번지지 않게 한다.

### 3.2 위치 기반 B 제거와 집계

- 기본안: 면당 256×256 마스크로 시작한다. 원판 밖 픽셀은 집계·쓰기에서 제외하고 앞뒷면은 동일한 면적 가중치를 쓴다. 초기 오염 패턴은 재현 가능한 고정 패턴이다.
- CPU 배열+Texture2D를 우선 검토하고 필요성이 확인되면 RenderTexture 방식을 선택한다. 어느 방식이든 상태 원본은 하나로 두고 화면·HUD·완료가 같은 상태를 사용한다. 매 프레임 동기 GPU 읽기나 전체 텍스처 재생성을 피한다.
- 유효 접촉 영역의 오염만 `제거 속도 × 접촉 시간 × 브러시 가중치`로 감소시킨다. 정지 Hold를 지원하고 값은 0~1로 제한한다. 빠른 드래그는 같은 면의 연속 접촉 사이를 보간하되 **프레임의 총 적용 시간을 표본 수로 나눠** 제거량이 늘지 않게 한다.
- 동전 밖·UI·MMB 회전·포커스 이탈·도구 전환·면 전환 때 이전 접촉을 끊는다. 재진입 지점까지 가상의 긴 선을 그리지 않는다. 기존 입력 차단을 우회하는 별도 청소 루프를 만들지 않는다.
- B 제거율 = `1 - 현재 유효 영역 오염 합 / 판 시작 오염 합`. 분모는 판 시작에 고정하고 초기 합 0이면 100%다. 빈 배경 픽셀과 옆면 때문에 진행률이 부풀지 않게 한다.
- Step 1의 전체 B 감소 경로는 교체한다. 마스크와 이전 스칼라를 동시에 감소시키지 않는다. 기존 `SurfaceDirtRemovalRatio`, 진행 이벤트, Reset 경로는 유지하거나 모든 소비자를 함께 이관한다. 위치 없는 기존 API를 유지한다면 전체 청소를 몰래 수행하는 호환 경로로 두지 않는다.

### 3.3 광택·머티리얼·외형

- 기본안은 B와 같은 좌표의 별도 광택 채널이다. 접촉 영역에서 광택을 올리고 **해당 위치의 잔여 B 오염**으로 효율을 낮춘다. 한 점만 문질러 동전 전체 광택을 완성할 수 없게 한다.
- 전체 광택은 유효 앞뒷면의 면적 가중 평균으로 집계한다. B가 없는 초기 구성에서도 광택은 별도로 진행된다. 청결도는 기존 A/B 제거율 평균을 유지한다.
- URP 호환 셰이더 또는 Shader Graph에서 오염 색·금속성·거칠기와 광택을 함께 표현한다. `CoinSurfaceContamination`의 기존 URP Lit 속성 검사와 PropertyBlock 갱신도 새 머티리얼 계약에 맞춰 수정한다.
- 동전 1종에 테두리·앞뒷면 구분·간단한 무늬를 넣어 청소 전후가 드러나게 한다. 표면 좌표 계약 확정 후 외형을 다듬고 Collider·A 오염 부착·가시성을 다시 확인한다. 커서·장식·효과가 청소 Raycast를 막지 않아야 한다.
- 런타임 마스크·머티리얼은 동전 인스턴스가 소유한다. 공유 에셋을 덮어쓰지 않으며 재시작 때 초기 상태로 복원하고 종료/파괴 때 생성 자원을 해제한다. 밝기만 올려 광택을 대신하지 말고 회전 시 반사 변화도 확인한다.

### 3.4 도구·효과·소리

- 도구별 반경·역할·선택 표시를 유지하고 접촉 중 반응을 구분한다. 작은 솔의 A 제거 반응, 천의 표면 닦임, 광택천의 마무리 반응을 최소 한 가지씩 제공한다.
- A 제거 순간 짧은 효과·소리, 유효 도구 사용 중 마찰음, 완료 시 짧은 피드백을 연결한다. AudioSource를 매 프레임 생성하거나 원샷 소리를 매 프레임 중첩하지 않는다.
- 소리·효과는 사용 상태와 실제 변화 정보를 받아 표현만 한다. 오염 수치나 완료 판정의 소유자가 되지 않는다. UI·MMB·포커스 이탈·완료·재시작에서 지속 효과를 확실히 정지한다.
- 3~5분은 Step 1 수치를 그대로 적용해 보장되지 않는다. 면적·반경·도구 교체·회전에 따라 실측하고 속도를 조정한다. 강제 대기나 불필요한 반복으로 시간을 맞추지 않는다.

### 3.5 UI·완료·최소 보관

- 화면 안에 짧은 키 안내, 도구 이름·역할, 선택 상태와 A/B/광택 진행을 제공한다. 앞뒷면 청소 필요와 다음 행동을 이해할 수 있게 하고 긴 설명·필수 팝업을 피한다.
- 완료 시 결과 수치를 고정하고 깨끗해진 동전을 잠깐 보여준 뒤 작은 트레이 등 지정 위치로 옮기는 연출을 기본안으로 한다. 한 세션의 마지막 동전 1개만 표현하며 재시작 때 반환/제거한다. 저장·인벤토리 시스템을 만들지 않는다.
- 연출 중에도 재시작을 안전하게 처리한다. 재시작은 진행 중 연출·소리·효과를 취소한 뒤 동전 부모·자세·마스크·A 내구도·UI·입력·시간·기본 도구를 복원한다. 중복 완료·중복 보관을 막고 결과 상태에서는 청소 입력을 받지 않는다.

## 5. 필수 검증과 완료 판정

- **좌표·분리:** 동일 위치 Hold, 빠른 Drag, 앞/뒤/옆/이음새·가장자리, X/Z 복합 회전, 0°·45°·75°·180°, 줌 극값. 보이는 면만 변화하고 반대면·접촉 밖 변화가 없어야 한다.
- **수치:** 초기 B=0·부분 오염·전체 오염, 유효 영역 집계, 제거율·광택 0~1, 세 완료 기준의 직전/동일/직후. 같은 총 시간·경로를 30/60/120Hz 표본으로 입력해 결과 차이를 비교한다(기본 허용 오차 1%p, 초과 시 원인 기록). 순수 마스크·집계 로직에 작은 회귀 테스트를 둔다.
- **입력·수명:** 기존 `s1-06-f2`의 실제 LMB/UI/MMB/F/Wheel/포커스/타이머 검증을 이어받는다. 첫 청소→완료→재시작→재완료를 최소 2판 확인하고, 연출 중 재시작도 포함한다. 텍스처·머티리얼·소리·효과·이벤트가 누적되지 않아야 한다.
- **플랫폼·성능:** Unity 컴파일·Console·참조 확인 후 `Builds/Windows/Step2-<날짜>-<구분>/`에 Windows x64 빌드한다. 기존 산출물은 보존하고 Git에서 제외한다. 실제 화면·입력·셰이더·소리를 확인하고 PC 사양·프레임 시간·청소 중 GC/자원 증가를 기록한다. 초기 성능 목표는 1280×720에서 60fps이며 기기와 측정 구간을 명시한다.
- **외부 체험:** 구현에 참여하지 않은 사람 최소 1명이 개발자의 실시간 설명 없이 5~10분 체험한다. 첫 유효 청소부터 완료까지 시간(포커스 이탈 별도), 이해한 도구 차이, 막힌 지점, 청소·광택 만족/불만을 기록한다. 목표 밖이면 원인·수정·재시험 결과를 남긴다. 테스트 모집·메시지 전송은 사용자에게 맡긴다.

코드/API 통과, Windows 실제 입력 통과, 외부 체험 결과를 구분한다. 외부 체험이나 필수 실행이 없으면 **구현 완료·검증 대기**로 보고할 수 있으나 Step 2 전체 완료로 표시하지 않는다. Step 2 빌드에서 f2를 통과하면 해당 빌드 기준으로 Step 1 기록에도 연결하고 과거 Step 1 빌드를 검증했다고 쓰지 않는다.
