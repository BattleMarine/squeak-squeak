## 1. 목적·결정 상태 (Ra-1)

**같은 도구라도 재질과 오염 상태에 따라 반응이 달라 도구를 바꿀 이유가 생기고, 과정은 간단한가?** 이를 확인하는 작은 실험이다. 사용자의 “우선 권장안으로 Ra를 진행” 지시에 따라 아래 표본·도구·풀림·완료/보관 규칙을 이번 실험의 설계 기준으로 채택했다. 수치는 초기 튜닝값이며 Rc 체험으로 조정한다. 최종 게임 전체의 확정 사양이나 현실 동전 세척 지침이 아니다. Rb 구현은 별도 단계다.

| 구분 | 채택한 실험안 | 이유 |
| --- | --- | --- |
| 재질 | 가상 단일 합금 M1(동색), M2(은색). 동일 원판 크기·형상·오염 배치 | 외형/오염량 변화와 재질 반응을 분리해 비교 |
| 오염 | A: 부착 찌꺼기, B: 얇은 오염막 | 기존 오브젝트/양면 마스크 재사용. 부식·파티나 제거는 제외 |
| 도구 | 칫솔·천·스포이드 세척액 | 칫솔/천의 제거 역할과 세척액의 국소 상태 전환을 비교 |
| 확인 | 작업 중 게임 스캐너 토글 1개 | 남은 오염을 찾는 비용을 줄임. 현실 UV 검출 능력을 재현하는 기능은 아님 |
| UI | 임시 도구 버튼·스캐너 토글·진행 게이지 하나·보관/다음 작업 | 정식 도구함·손 애니메이션 없이 반응부터 검증 |
| 결과 | 청소 완료 후 남은 부분을 더 닦거나 보관 선택 | 목표 달성과 최종 표면 확정의 경계를 시험 |

- M1/M2는 **색으로만 구분되는 현재 CoinDefinition과 달리 반응 프로필을 갖는 제안**이다. 실제 합금의 이름·성질로 단정하지 않는다. 후속 사실 검증/아트 작업 때 명칭과 반응을 조정한다.
- 실험은 두 재질에 동일한 A/B 배치를 사용한다. 앞뒤 모두 A/B가 있고, 재료별 반응 이외의 변수는 동일하게 둔다. 재현용 고정 배치부터 사용하며 랜덤 생성은 아직 필요 없다.
- 컴파운드/면봉·고급 마모·도금·보존 평가·NPC 경고·자동 장비·전시실·제작기·공유·경제는 제외. 광택은 이번 표본에서 수치를 고정하고 완료 조건에서 제외한다. **최종 게임의 광택 필수 여부는 여전히 미정**이다.
- 기존 3도구/3단계와 선호 속도 원본은 유지한다. 실험용 정의를 분리하고 기존 enum/ID/GUID를 재해석하지 않는다. 기존 광택천을 스포이드로 바꿔 저장하는 식의 우회는 금지한다.
- 모든 실험 도구는 시작부터 사용 가능하다. 정식 소유권을 변경하지 않는 명시적 실험 구성을 사용하며, 현재 stage-01의 잠금 정책은 별도로 보존한다.

## 2. 반응과 상태 (Ra-2)

### 최소 상태

- A는 현재 내구도와 제거 상태를 유지한다. B는 위치별 초기/현재 오염량(0~1)을 유지한다.
- B에 위치별 `풀림 여부`를 추가하는 안이다. 세척액 한 방울의 유효 반경 안에서, B가 남은 텍셀만 즉시 풀림 상태가 된다. 대기 시간·자동 제거·증발·추가 물기 청소는 없다.
- 풀림은 판 내에서 유지하고 B가 0이면 해제한다. 중복 도포는 중첩되지 않고 제거 성능이 무한히 오르지 않는다. 도포는 오염량·진행률·광택을 바꾸지 않는다.
- 풀림 표시와 실제 제거는 같은 상태를 참조한다. 새 판/재도전에서 모두 초기화한다. 숨겨진 손상/보상은 없다.

### 반응표 — 숫자는 초기 효율 계수

| 도구 | A / M1 | A / M2 | B 미처리 / M1 | B 미처리 / M2 | B 풀림 / M1 | B 풀림 / M2 |
| --- | --- | --- | --- | --- | --- | --- |
| 칫솔 | 1.0, 찌꺼기 축소·분리 | 1.0, 동일 | 0 | 0 | 0.25, 조금씩 걷힘 | 1.0, 솔질 자리가 또렷이 드러남 |
| 천 | 0 | 0 | 0.5, 얇아지며 닦임 | 0, 막이 유지됨 | 1.0, 넓게 닦임 | 0.25, 잔여막이 느리게 걷힘 |
| 스포이드 | 변화 없음 | 변화 없음 | 국소 풀림 전환 | 국소 풀림 전환 | 변화 없음 | 변화 없음 |

M1은 `칫솔로 A → 천으로 B`가 가능하며 세척액은 B 제거를 돕는다. M2는 `칫솔로 A → 세척액 → 칫솔 또는 천으로 B`가 가능하고 풀린 막에는 칫솔이 빠르다. **천 하나/칫솔 하나/약품만으로 두 혼합 표본을 모두 끝낼 수 없다.** 반면 칫솔은 A와 풀린 B, 천은 미처리/풀린 B를 처리한다. 숫자 차이가 실제 표면에서 읽히는지는 Rc에서 판정한다.

| 조절값 | 제안 시작값·단위 | 적용 |
| --- | --- | --- |
| A 기본량 | 기존 작은 솔의 1.25 내구도/유효 문지름 초 | 반응표 A 계수를 곱함. 천/스포이드 0 |
| B 기본량 | 4.8 오염 강도/유효 문지름 초 | 모든 실험 제거 도구가 같은 기준량×표 계수 사용. 기존 자산은 수정하지 않음 |
| 칫솔/천 반경 | 기존 .18 / .32 월드 단위 | 실제 접촉 면 안에서만 적용 |
| 스포이드 반경 | .18 월드 단위 | 한 클릭당 한 도포. 경계 안 유효 텍셀에 적용 |
| B 완료 기준 | 양면 초기량 대비 95% 제거 | 4절 계산에 사용; Rc에서 체감 조정 가능 |

- 무효 도구는 선택 가능하다. 오염 변화가 없으면 제거 파편·제거 완료음·진행 증가를 만들지 않는다. 마찰음과 도구 접촉 표현은 허용한다.
- 풀림은 젖은 듯한 국소 색/질감 변화와 짧은 방울 소리로 표현한다. 제거가 아니므로 게이지는 오르지 않는다. 시간 경과만으로 닦이거나 큰 손상 경고를 내지 않는다.
- 원치 않는 화면 얼룩으로 보이지 않도록 B가 남은 영역에만 풀림 표시를 제한한다. 이미 깨끗한 곳에 클릭해도 가짜 오염·진행이 생기지 않는다.
- A와 B가 겹치면 각자 상태에만 도구 효과를 적용한다. A에 가려진 B로 약품이 통과하는 물리 모델은 이번에 만들지 않는다. 표본 배치는 A와 주요 B 시험 구역을 분리해 해당 모순이 핵심 체험에 개입하지 않게 한다.

## 3. 도구별 입력·오염 확인 (Ra-3)

| 대상 | 사용 입력 | 차단·재개 규칙 |
| --- | --- | --- |
| 칫솔·천 | LMB를 누른 채 실제 이동 | 기존 공통 문지르기 예산 유지. 최초 접촉/정지/재클릭 0, 같은 프레임 중복 적용 금지 |
| 스포이드 | 유효 동전 표면에서 LMB 눌림 1회당 한 방울 | Hold/드래그 자동 연사 없음. 클릭 당시 접촉만 사용하며 궤적 전체 도포 금지 |
| 스캐너 | 임시 UI 토글로 켜기/끄기 | 도구 선택을 바꾸지 않음. 켠 채 청소 가능. 색상·강도로 현재 잔여 B, A 외곽 표시 |
| 관찰 | MMB 회전 / Wheel 줌 / F 자세·줌 복원 | 상태·진행률·풀림 보존. 회전/줌과 동시 도구 사용 차단; 다음 문지름 기준점 재설정 |

- 공통 차단: UI 위, 포커스 상실, 준비/저장/포기 확인 중, 유효 표면 접촉 없음. 복귀 시 누르고 있던 스포이드 버튼에서 새 방울을 만들지 않고 놓았다가 다시 눌러야 한다. 도구 교체 후에도 새 눌림이 필요하다.
- 스캐너는 판정 데이터를 읽는 표현이다. 청소·완료·타이머 시작을 발생시키지 않는다. 관통해서 뒷면 오염을 표시하지 않으며 회전해 확인한다. 기존 손상/원래 문양/풀림 자체는 오염으로 표시하지 않는다.
- 적합 도구 이름이나 “오염이 풀리고 있어요” 같은 정답/상시 문구는 띄우지 않는다. 버튼 이름·조작법·종료/오류 고지는 표시 가능하다.
- 시간은 첫 실제 A/B 제거 또는 첫 유효 풀림 전환에서 시작한다. 그 뒤 작업대의 전경 활성 시간은 관찰·스캐너 시간을 포함해 누적한다. 포커스 상실·포기 확인·작업대 이탈·저장 중에는 멈춘다. 이번 실험에는 시간 등급/페널티가 없다.

## 4. 단일 진행률·완료 (Ra-4)

재질/도구가 달라도 같은 제거량이면 같은 진행률이다. 초기 양면 상태를 판 시작 시 고정하고 도구/카메라 변경으로 분모를 바꾸지 않는다.

- A 제거율 `rA = 제거된 오브젝트 수 / 초기 오브젝트 수`. 기존 집계를 재사용하며 완전히 제거한 개체만 집계한다. A 목표 `qA=1.0`.
- B 제거율 `rB = 1 - 양면 현재 B 합 / 양면 초기 B 합`. 유효 동전 텍셀만 합산한다. B 목표 `qB=0.95`.
- 존재하는 오염 종류만 집계 집합에 포함한다. A/B 각각 `p = clamp(r/q, 0, 1)`이며 단일 게이지는 존재 종류의 p를 같은 가중치로 평균한다. 한 종류만 있으면 그 p, 둘 다 없으면 준비 완료 후 1이다.
- **완료는 모든 존재 종류의 r이 각 q 이상일 때**다. 표시 반올림으로 완료시키지 않는다. 미완료 동안 정수 퍼센트 표시는 최대99, 완료 시100이다. 준비 실패/미초기화는 빈 동전 완료로 보지 않는다.
- A/B 진행은 앞뒤 합계다. 앞뒤를 균등 배치한 표본에서 한 면만 청소하면 완료할 수 없어야 한다. 극소량이 반대면에만 남는 일반 생성 규칙은 이번 고정 표본 밖이며 추후 별도 결정한다.
- 초기 손상·금속색·풀림·광택은 분모와 목표에서 제외한다. 스포이드/스캐너만 사용해서 완료되지 않는다.
- 허용 잔여 B도 스캐너에는 실제 양으로 보인다. 100%는 오염이 수학적으로 0이라는 뜻이 아니라 청소 목표 충족이다. 완료 후 더 닦기는 가능하며 게이지는100을 유지한다.

예시: A 전부 제거+B 절반 제거이면 `(1 + .5/.95)/2 = 76.3%`. A 전부+B95%이면100%. A만 있으면 전부 제거할 때100%, B만 있으면95%에서100%다.

## 5. 청소 완료·보관·종료 (Ra-5)

다음은 새 상태 계약 제안이며 현재 코드와 다르다. 보관이 최종 결과를 확정한다. 자동 전시 이동은 없다.

| 상태/행동 | 입력·시간·데이터 |
| --- | --- |
| 준비 | 입력/완료 차단, 정의·초기 오염/풀림·참조 검증. 성공한 뒤만 청소/완료 가능 |
| 청소 중 | 유효 도구 사용 허용, 3절 시간 규칙 적용 |
| 청소 목표 달성 | `청소 준비완료` 알림은 판당1회. 제거 도구·관찰 허용, 타이머는 보관까지 계속. 완료 연출로 포인터를 끄거나 강제 트레이 이동하지 않음 |
| 보관 확인 | 목표 달성 때만 진입, 도구 입력/시간 정지. 취소하면 경과 시간을 초기화하지 않고 그대로 재개. 승인은 최신 표면을 한 번 복제해 불변 결과로 확정 |
| 저장 대기/실패 (S3-03) | 동일 결과 ID·스냅샷으로 재시도. 성공 전 다음 판 생성/보상/보관 성공 표시 금지. 실패 취소는 현재 작업으로 복귀하며 실패 스냅샷 폐기; 추후 재확정 정책은 저장 계약에서 검증 |
| 보관 성공 | 현재 결과를 더 수정하지 않음. 감상/다음 동전 선택. 다음 동전은 작업대에서 명시적으로 시작하며 새 판 ID 부여 |
| 새 동전/포기 | 미보관 판이 있으면 폐기 확인. 취소는 현재 상태/시간 그대로, 확정은 보상 없이 해당 판 폐기 |
| 방 안 이동 (후속) | 현재 판 유지, 도구 입력/시간 일시정지. 복귀만으로 생성/초기화하지 않음 |
| 앱 종료 | 미보관 작업이 있으면 저장되지 않음 고지와 종료/취소. 취소는 작업 유지. 종료 시 폐기, 이미 저장된 결과/일반 진행은 유지 |

- Rb에서는 디스크 저장을 만들지 않는다. 보관 스냅샷은 시험용 메모리에만 유지하며 UI에 `시험용 보관 · 종료 시 사라짐`을 명시한다. 다음 동전으로 갈 때도 이전 결과 스냅샷의 불변성을 검사한다. 영구 전시 기능이 완성됐다고 보고하지 않는다.
- S3-03 권장 범위는 **최소 완성 동전 1개 이상을 원래 상태로 다시 읽는 저장 왕복**과 일반 진행의 분리다. 대규모 전시·압축 최적화·공유는 후속이다. 파일 저장/복원 채택 범위는 Rc 이후 사용자와 확정한다.
- 최종 게임의 선택 광택을 채택한다면 목표 달성 상태에서 후처리를 허용하고 보관 시점에 결과를 확정하는 안을 권장한다. 이미 보관한 결과의 재작업·갱신은 이번에 다루지 않는다. 이번 표본에는 광택 입력을 제공하지 않는다.
- 결과/미래 보상은 `결과 ID + 판 ID`로 중복 확정을 막는다. 목표 달성과 보관 이벤트를 혼용하지 않는다. 실제 거래·재실행 중복 방지는 S3-03 이후 저장과 함께 검증한다.
- 저장 실패에서 편집으로 돌아간 뒤 다시 보관하면 새 스냅샷/요청 ID를 발급한다. 취소된 이전 요청의 늦은 성공 콜백은 현재 판을 전환시키지 못해야 한다. 실패 취소를 허용하기 전 저장소가 취소/확정 여부를 보장할 수 있는지 S3-03에서 검증하고, 결과가 불명확하면 취소 대신 재조회/재시도로 제한한다.

### Rb 권장 분할

1. **Rb-0 기준선:** 실제 연결 프로젝트/Editor·Dirty·Console 조회, 최근 UI/마스크 참조와 광택 문제 확인. 사용자 변경 보존. 고쳐야 할 기존 결함은 별도 범위로 보고.
2. **Rb-1 반응 원본:** 실험 정의·반응 조회·풀림 상태·순수 경계 검사. 기존 stage-01~03 회귀 유지.
3. **Rb-2 입력/표현:** 스포이드·스캐너·반응 효과 연결, 실제 접촉/차단·앞뒤/회전 검사.
4. **Rb-3 진행/보관:** 단일 게이지·상태 전환·메모리 결과·반복 초기화 통합. 명시적 실험 진입 경로와 수동 실행법 인계.

Rb는 구현 승인 후 위 단위로 진행한다. 임시 입력 우회·전역 도구 해금·실험을 기존 판에 자동 적용하지 않는다. Unity 씬/에셋은 목적에 맞는 도구로 편집하고 기존 양면·문지르기·초기화 검증을 재사용한다.

### 자동/수동 검증 사례

- 반응표 12개 제거 셀과 스포이드 상태 전환을 검사. 같은 위치에서 도포만 반복해도 오염량/게이지 불변, 유효 첫 도포만 상태·타이머 변화.
- 정지/재클릭은 천·칫솔 제거0, 스포이드는 한 새 클릭에 한 방울. UI·포커스 복귀·도구 변경·MMB/Wheel/F 후 의도하지 않은 사용 없음.
- 반대면·표면 밖은 불변. 풀림 영역 경계 밖의 미처리 B에 풀림 효율을 적용하지 않음. 판 초기화 후 풀림0/초기 오염 복원.
- A만/B만/양쪽/없음, 준비 실패, B 목표 바로 아래/정확히 경계, 표시 반올림, 앞면만 제거를 검사. 화면과 판정에 별도 계산식 금지.
- 목표 달성 후 추가 청소 가능, 보관 취소 유지, 확정 스냅샷 불변·중복 확정 없음, 다음 판 생성 시 이전 데이터/구독/텍스처 누적 없음.
- Rb 메모리 보관과 S3-03 영구 저장을 구분. S3-03에서 실패/재시도·종료·재실행·최종 양면 외관/수치 복원을 실제 저장 파일로 검사.

### Rc 체험·판정

사용자는 동일 배치의 M1/M2를 순서 바꿔 두 번 체험한다. 첫 회는 조작 안내만 제공하고 정답 도구/순서는 알려주지 않는다. 외부 무안내 체험은 기존 S3-C05와 별도로 미완료 상태를 유지한다.

| --- | --- |

시간·클릭·도구 교체 횟수와 막힌 지점을 기록하되 이번에 시간 등급을 강제하지 않는다. 사용자 만족 확인 전 “재미 통과”로 표시하지 않는다. 반응표의 자동 검사 성공은 체험 성공을 대체하지 않는다.

Ra의 실험 선택에 관한 사용자 결정과 후속 “검토하고 다음 단계” 요청을 반영했다. 오케스트레이션에서 문서·기존 연결점·경계 조건을 재검토하고 Ra 인계를 마쳤다. 별도 모델의 독립 검토는 수행하지 않았다. 이전에 추가한 별도 검토 대기 조건은 이번 오케스트레이션 검토 기록으로 정리하며, 이미 채택한 선택을 다시 묻지 않는다. 이후 사용자 요청으로 Rb-0~3을 구현했다. 검증 범위·잔여 수동 확인은 [Rb 검증 기록](../AI/Step3RbValidation.md)을 따른다.

### 교차 검토 보완

- 반응표의 계수는 접촉 영역 안의 제거량이다. 칫솔/천 반경이 달라 면적당 계수만으로 전체 완료 속도를 단정하지 않는다. Rc에서 동일 오염 영역의 실제 소요 시간·교체 이유를 비교하고 필요하면 실험 정의만 조정한다.
- 목표 달성은 내부 상태 이벤트이며 상시 설명 문구를 추가하라는 뜻이 아니다. 보관 버튼 활성화·게이지와 기존 효과음으로 전달한다.
- B 목표 경계는 원본 수치로 판정한다. 표시 반올림과 부동소수 오차 때문에 상태가 왕복하지 않도록 완료 알림을 판당1회 유지하며, 실제 비교 방식의 경계 사례는 Rb 자동 검사에 포함한다.
- B 완료 비교는 초기 합 대비 잔여 비율을 사용하고, 허용 오차는 정규화 비율 기준 최대 `1e-6`으로 제한한다. 초기 합0은 존재 종류에서 제외한다. 목표 바로 아래/경계/초과와 매우 작은 초기 합을 검사하며, NaN/무한·음수 입력은 완료로 보정하지 않고 준비 오류로 거부한다. HUD도 같은 판정 결과를 읽는다.
- 공간 이동은 후속 후보이고 현재 Rb가 방 전체 이동을 구현할 의무는 없다. 저장 실패/재실행 검증 역시 S3-03 책임이며 Rb-3는 메모리 스냅샷까지만 검증한다.
