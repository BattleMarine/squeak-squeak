### 청소 속도 기준

사용자는 **세 도구의 A/B/광택 속도 모두 10배**가 만족스럽다고 확인했다. 반경은 유지한다. S3-00에서 저장값·에디터 메모리값을 구분하며, 선호값의 적용 여부를 추측하지 않는다.

| 도구 | 준비 시 디스크 A / B / 광택 | 사용자 선호 목표 A / B / 광택 | 반경 |
| --- | --- | --- | --- |
| DryCloth | 0.04 / 0.48 / 0.12 | 0.4 / 4.8 / 1.2 | 0.32 |
| SmallBrush | 0.125 / 0.12 / 0 | 1.25 / 1.2 / 0 | 0.18 |
| PolishingCloth | 0.015 / 0.24 / 0.48 | 0.15 / 2.4 / 4.8 | 0.28 |

S3-00 조회에서 세 도구의 에디터 메모리는 선호 목표와 일치하고 모두 Dirty=true, 디스크는 표의 이전 값임을 확인했다. CleaningRoom에도 저장되지 않은 변경이 있어 그대로 보존했다.

S3-01a에서 작업 직전 값을 재조회하고 **목표 절대값으로 한 번만** 반영·저장·회귀 검사한다. 이미 목표값이면 다시10배 하지 않는다. 이후 사용자 조정이 있으면 덮어쓰지 않고 새 기준을 기록한다. 도구 에셋별 저장을 사용하고 관련 없는 Dirty 씬·에셋을 일괄 저장/재로드하지 않는다. 기존 10/12 빌드에는 이 추가10배가 포함됐다고 간주하지 않는다. 마른 천 능력 제한·광택 표현 수정은 이 준비 작업에 섞지 않는다.

## 3. 최소 콘텐츠·진행 기본안

### 문지르기 입력 계약 (2026-10-13 사용자 승인)

- A/B/광택·효과/소리는 포인터가 프레임당 계산한 같은 문지르기 샘플을 읽는다. 여러 소비자의 조회는 샘플을 소모하지 않으며 A/B 소유자는 같은 샘플을 각1회만 적용한다.
- Inspector `minimumRubDistance` 기본0.001 **월드 단위**: 작은 이동을 누적한다. `referenceRubSpeed` 기본0.6 **월드 단위/초**: 기존 도구 초당량을 유지하며, 이동 거리/기준 속도와 실제 이동 프레임 시간 중 작은 값을 적용 예산으로 사용한다. 정지 시간은 예산으로 누적하지 않는다.
- 최초 접촉·재클릭·UI/표면 이탈·포커스·도구/판 교체·MMB/Wheel/F 이후에는 기준점만 잡는다. 유효 연속 드래그만 A/B/광택을 변경하며 A/B 모두 같은 구간을 분할해 예산을 나눈다. 도구 선호 속도값은 재조정하지 않는다.
- 합성 CPU/Scene API 검사와 실제 프레임의 Input System 가상 장치 검사, 물리 마우스/육안 검사를 구분한다. 현재 환경의 가상 장치 실제 프레임 검사는 포커스 상실로 차단되었으며 입력 조건을 우회하지 않았다. 상세 근거/재현은 체크리스트와 [검증 안내](AI/Step3RubbingValidation.md)를 따른다.

- 동전 외형 **2종**, 고정 스테이지 **3개**, 기존 도구 **3종**, 재화 **1종**, 로컬 저장 슬롯 **1개**.
- 두 외형은 같은 검증된 원판 Mesh/Collider 계약을 사용하고 색·문양으로 구분해도 된다. 스테이지별 A 배치/내구도·B 패턴/강도를 구분한다. 실제 산화 반응·새 오염 시뮬레이션은 만들지 않는다.
- 시작 시 마른 천만 보유. 단계별 완료 목표를 낮춰 잠긴 도구 없이도 반드시 완료할 수 있게 한다. 고정 전역 목표를 억지로 통과시키는 우회는 금지한다.

| ID | 구성·목적 | 입장 조건 | 완료 목표 A/B/광택 | 첫 완료 효과 |
| --- | --- | --- | --- | --- |
| stage-01 | 동전 A, 가벼운 A/B; 기본 조작 | 처음부터 열림 | 0.9 / 0.8 / 0 | 재화100, stage-02 및 작은 솔 구매 자격 |
| stage-02 | 동전 B, 큰 먼지와 다른 얼룩 배치 | stage-01 완료 + 작은 솔 보유 | 0.9 / 0.8 / 0 | 재화100, stage-03 및 광택천 구매 자격 |
| stage-03 | 동전 A의 다른 복합 배치; 광택 포함 | stage-02 완료 + 광택천 보유 | 0.9 / 0.8 / 0.7 | 재화100, 준비된 단계 완료 안내·재플레이 |

- 작은 솔 가격60, 광택천 가격100. 시작 재화0. 최소 보상 경로는 `100−60+100−100=40`으로 구매 막힘이 없어야 한다.
- 구매 자격 해금과 소유를 구분한다. 사용 도구는 `소유 도구 ∩ 해당 단계 허용 도구`이며 선택 UI와 실제 사용 검사가 동일한 목록을 따른다.
- 완료한 단계는 재플레이 가능. 프로토타입은 **단계별 첫 완료 보상만** 지급하고 UI에 표시한다. 재플레이는 최고 등급 갱신만 가능하며 반복 보상 경제는 후속이다.
- 제외: 영구 수집·전시, 랜덤 무한 모드, 대규모 콘텐츠, 도구 강화, 클라우드 저장, 다중 슬롯, 청소 도중의 마스크/카메라 상태 저장, 새 메뉴 씬, 새 도구 제작.

### 단계 전환

- 단계 정의를 입력 차단 상태에서 모두 검증한 뒤 적용한다. 부분 적용 중 청소/완료 검사를 돌리지 않는다. 실패하면 이전 안전 상태/선택 화면에 머물고 오류를 알린다.
- A 배열의 개수·초기 내구도와 Removed 구독을 새 배치에 재설정한다. 현재 `ObjectDirtCleaner`는 Awake에서 배열을 집계하므로 오브젝트만 교체하면 안 된다.
- B/광택 초기 패턴·완료 목표·외형·도구 목록·기본 도구를 먼저 설정한 뒤 새 판 초기화한다. 이전 마스크·연출·부모/Transform·커서·소리·타이머가 남지 않게 한다.
- `RestartRound()`는 현재 완료된 판의 재시작 전용이다. 다음 단계/중도 포기에서는 완료 플래그를 조작해 우회하지 말고 공통 초기화 절차를 명시적으로 분리한다.
- 단계 선택 패널을 여는 동안 진행 타이머/입력이 계속 흐르지 않도록 상태를 정의한다. 청소 중에는 선택 화면 이동 전 포기 확인, 취소 시 기존 판 유지. 포기는 보상을 주지 않고 해당 판만 폐기한다.
- 표면·A·입력·완료·표현 참조를 명시적으로 다시 연결한다. 단계 전환마다 중복 싱글턴/구독/마스크/AudioSource가 늘지 않는다.

### 결과·보상·구매

- 결과 등급 기본안: 완료 시 시간≤180초 A, ≤300초 B, 그 외 C. 임시 스테이지 데이터 값으로 노출하고 정확한 경계 검사를 한다. 시간제한·실패·강제 대기는 없다. 저장할 시간은 포커스 제외 게임 타이머이며 실측 목표와 혼동하지 않는다.
- 등급은 결과 시점에 고정한다. 재화는 등급과 무관한 첫 완료 고정100으로 시작한다. 최고 등급만 개선하고 동일 등급이면 짧은 시간을 보존한다.
- 완료 처리의 `재화 + 완료 ID + 최고 결과 + 해금 근거`는 한 거래다. 같은 판 콜백·중복 클릭·재접속으로 재지급되지 않아야 한다.
- 구매는 자격·미소유·잔액·유효 가격을 다시 검사하고 차감과 소유권 추가를 한 거래로 처리한다. 재구매·음수 잔액·잠긴 도구 직접 선택을 막는다.
- 저장 실패 시 거래 성공을 표시하거나 다음 단계로 보내지 않는다. 재시도 시 중복 차감/지급 없이 같은 거래를 처리한다.

## 5. 저장 계약

- `Application.persistentDataPath` 아래 버전 포함 JSON 한 슬롯. 최초 버전1: `schemaVersion`, 재화, 완료 stage ID 목록, 소유 tool ID 목록, 단계별 최고 등급/시간, 선택 stage ID. 해금 가능 상태는 정의+진행에서 계산한다.
- 청소 도중 종료하면 해당 단계의 **처음부터** 시작한다. 완료 보상·구매는 성공한 저장까지만 유지한다. 종료 콜백에만 저장을 의존하지 않는다.
- 새 진행 사본을 검증→임시 파일 쓰기/닫기→본 파일 교체·이전 유효본 백업→메모리/화면 확정. 본 파일을 먼저 비우지 않는다. 교체 실패면 이전 진행을 유지하며 완료 화면의 미저장 거래 재시도만 허용한다.
- 로드 시 본 파일 우선, 손상됐으면 유효 백업 복구를 알린다. 실패 원본은 보존한다. 둘 다 없을 때만 신규 진행 생성. 둘 다 손상되거나 미래 버전이면 자동 초기화/덮어쓰기를 하지 않고 안내·재시도 상태로 둔다.
- ID 중복·미정의 ID·음수 재화·NaN/무한 시간·잘못된 등급·불가능한 소유/완료 조합을 검증한다. 호환 규칙 없이 조용히 삭제/정규화하지 않는다. 데이터 ID 개명은 명시적 이전 규칙이 필요하다.
- 사용자 저장으로 테스트하지 않는다. 임시 별도 경로에서 빈 파일·손상·백업·쓰기 실패·중단 시점·미래 버전을 검증한다. 자동 저장 테스트 파일은 Git 제외한다.

세부 a/b 단위와 진행은 [체크리스트](AI/Step3ImplementationChecklist.md)에 둔다.

1. **S3-00 준비:** 현재 파일/Unity 기준선, 사용자 튜닝값 차이, 기존 연결점, 이월·범위 계약을 기록. 제품 변경 없음.
2. **S3-01 데이터:** 선호 속도 반영·회귀, 동전/단계/카탈로그와 검증기·시험 콘텐츠 정의.
3. **S3-02 단계 실행:** 안전한 초기화·선택/재도전/다음 단계·동전/오염 교체. 임시 전체 도구 허용은 개발 검사 전용이며 최종 해금 우회 금지.
4. **S3-03 저장 기반:** DTO·검증·안전 저장/로드·오류 처리. 이후 모든 진행 거래가 이 경로를 사용.
5. **S3-04 결과·진행:** 등급·한 번 보상·완료 기록·해금 조건과 저장 거래.
6. **S3-05 상점·도구:** 구매 자격·소유·잔액·사용 제한, 저장 실패/재시도.
7. **S3-06 UI 통합:** 단계 선택/다음 행동/잠금 이유/저장 오류/재개, 연출 중 전환·중도 포기.
8. **S3-07 최종 검증:** 새 저장으로3단계→2도구 구매→종료·재실행→진행 복원, 재플레이 보상 중복 없음. Windows 빌드·사용자 검사·이월 상태 보고.

각 단위는 컴파일/Console·데이터/참조·해당 동작 검사·보존 확인 후 인계한다. 금전/저장/전환은 실패 경로를 자동 회귀로 남긴다. 성능/시각/실제 입력을 수치 테스트 통과만으로 인증하지 않는다.

**Step 3 완료:** 새 시작부터 위 전체 흐름을 Windows에서 실행하고 저장 재개·중복 거래·구매 막힘 없음까지 확인한다. `Builds/Windows/Step3-<날짜>-<구분>/`에 별도 빌드하며 기존 빌드와 로그·저장은 커밋하지 않는다. 이월된 Step 2 품질 검증은 별도 상태로 남긴다.
