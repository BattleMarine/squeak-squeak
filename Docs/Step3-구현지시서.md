# Step 3 구현 지시서 — 청소 판단·진행 구조 프로토타입

작성: 2026-10-13. 대상: 구현 담당 AI. 진행 정본: [체크리스트](AI/Step3ImplementationChecklist.md).

## 1. 목표·작업 경계

**상태 관찰 → 도구 사용·반응 확인 → 청소 → 마무리·보관**의 작은 실험을 먼저 설계한다. 관찰/시험을 매번 거쳐야 하는 별도 절차로 강제하지 않는다. 2026-10-16 [GOAL](../GOAL.md) 대조 결과를 반영했다. GOAL은 이상향이며 모든 항목이 Step3 요구는 아니다. [설계 원칙](Design/CoinCleaningPrinciples.md)·스토리보드의 종전안과 충돌하면 이 문서의 현재 범위를 적용하고, 해당 참고 문서를 구현 근거로 사용하기 전에 대조한다. GOAL을 매 작업마다 읽을 필요는 없다.

- 먼저 [AGENTS](../AGENTS.md), [README](../README.md), [ROADMAP](../ROADMAP.md), 이 문서와 체크리스트의 최신 상태를 읽는다.
- 현재 승인 범위는 **S3-03a/b 전체 구현·검토 및 세부 단계별 커밋**이다. 사용자가 Ra 권장 실험안을 채택했고 오케스트레이션 검토를 완료한 뒤 Rb 전체 진행을 요청했다. S3-00~02 완료 이력은 유지한다. Rb-0 기준선부터 Rb-1 반응, Rb-2 입력/표현, Rb-3 진행/메모리 보관까지 구현·개발 검증했다. 실제 검증 범위·빌드는 [Rb 검증 기록](AI/Step3RbValidation.md)을 따른다. 사용자 재검사 후 이번 테스트를 종료했고 Rc 범위 판정을 정리했다. S3-03a 저장 DTO·안전 저장소 구현·검토를7f159eb로 커밋했으며 03b 제품 연결·개발 검증을 완료했다. 사용자 수동 검사는 대기다.
- 사용자 결정으로 Step 2 잔여 과제를 이월한다. Step 2 전체 완료로 표시하지 않는다. 원본 수동 기록과 기존 미커밋 변경을 보존한다.
- 아래 종전 콘텐츠 표·가격·등급은 **기존 정의 데이터와 당시 시험 계획**이다. 실제 보상·상점·저장 구현 완료를 뜻하지 않으며 새 설계의 확정 요구로 사용하지 않는다. S3-R에서 대응표·판정·최소 콘텐츠를 먼저 정하고 이후 저장/경제 계약에 반영한다.

### S3-R — 최소 청소 반응 실험 (Ra 검토 완료, Rb 테스트 종료/Rc 범위 판정 완료)

1. **Ra 문서 설계:** 아래 산출물로 소수 재질·오염·도구의 반응과 완료 규칙을 정한다.
2. **Rb 최소 구현:** 승인된 표본만 기존 원판·A/B·초기화 기반에 연결한다. 화면·단일 게이지·완료 판정은 같은 상태를 읽는다. 정식 3D 도구함 대신 임시 버튼을 사용할 수 있다.
3. **Rc 사용자 체험:** 같은 도구가 여러 상태를 처리하면서 재질/상태에 따라 선택을 바꿀 이유가 생기는지, 조작과 확인이 번거롭지 않은지 검사한다. 자동 검사만으로 재미를 통과 처리하지 않는다. 선택한 최소 범위의 채택·수정·이월을 결정하고 저장/진행 계획을 갱신한다.

#### Ra 인계·산출물

산출물: [S3-Ra 최소 청소 반응 실험](Design/Step3Ra-CleaningExperiment.md). 재질2·오염2·칫솔/천/스포이드와 게임 스캐너, 광택 제외 실험안을 사용자 지시로 채택했다. 오케스트레이션 검토 후 Rb에 인계하며 이미 채택한 선택은 반복 확인하지 않는다.

| 항목 | 작성할 내용·완료 기준 |
| --- | --- |
| Ra-1 최소 표본 | 단일 재질2종·오염2~3종·수동 도구3종 정도를 출발 제안으로 선정. 수량은 고정하지 않으며 포함/제외 이유와 기존 A/B 대응을 기록 |
| Ra-2 반응표 | `도구 × 재질 × 오염/처리 상태`별 효과·무효 조건·표면/효과음 반응·조절값·필요 시 위험을 작성. 같은 도구의 재질별 차이와 도구를 바꿀 이유가 드러나는 사례 포함. 실제 화학 법칙의 정밀 재현은 요구하지 않음 |

**Ra 완료:** 위 산출물과 오케스트레이션 문서 검토를 마치고, 미결정 사항에 권장안·결정 주체·결정 시점을 기록한다. Rb에 영향을 주는 결정은 구현 전에 확정한다. 문서 작성만으로 Rb 승인이나 기능 완료로 처리하지 않는다.

#### 범위와 후속 후보

- 도구 후보: 칫솔, 스포이드 시약병, 천, 이쑤시개/송곳, 컴파운드+면봉, 오염 확인용 UV/게임 스캐너. 전부 구현하지 않고 최소 조합을 고른다. 보호 도포기는 제외, 젤은 우선 제외. 5~15종은 장기 희망 규모다.
- 초기 수동 실험에서 만능 도구는 피하되 소유 잠금과 적합성을 구분한다. 부적합 도구를 모두 선택 불가로 만들어 시험할 기회를 없애지 않는다. 자동 장비는 이번 실험에서 제외하며 후반 편의 장비 후보로 남긴다.
- 도금·복합 구조, 고급 문양 마모·함몰·메시 변형, NPC 경고, 보존 평가, 제작기·공유·방 전체 연출은 Ra/Rb의 필수 조건이 아니다. 손상을 표본으로 채택할 때만 한도·인식 가능한 징후·검증을 정의한다. 깊은 기존 손상은 기본적으로 남고 동전 소멸·관통·절단은 제외한다.
- 보존은 선택 사항이며 사라진 문양 복구를 요구하지 않는다. 광택 필수 여부·점수·등급·경제·스테이지/무한 모드의 최종 채택은 미정이다. 기존 가격·보상·3단계는 시험 기준선일 뿐이다.
- 최종 방향은 단일 게이지·작업대 물체로 도구 선택/자동 정리·작업 중 오염 확인이다. 상시 설명 문구 없이 표면과 효과음으로 반응을 전달한다. 필수 조작/종료/오류 안내는 허용한다. UI 시안의 색상은 고정 기준이 아니다.

**Rb 착수 전 기준선:** 최근 저장된 CleaningRoom UI·Coin_Surface 마스크 참조와 S3-C02 광택 표현을 실제 에디터에서 확인하고 문제/기존 상태를 구분한다. 설계 문서 작성은 이 확인을 기다리지 않아도 되지만 시각 반응 체험의 신뢰성을 해치는 문제는 체험 전에 해결한다. 사용자 미저장 변경을 일괄 저장하거나 복원하지 않는다.

2026-10-17 사용자 테스트 종료 지시에 따라 [Rc 판정·S3-03 인계](AI/Step3RcDecision.md)를 현재 구현 범위의 정본으로 적용한다. S3-03은 완성 결과 최소 영구 저장·복원과 별도 일반 진행 책임을 다룬다. 상점/재화/등급/보상 신규 구현은 보류하며 아래 종전 DTO·가격·보상안을 구현 요구로 사용하지 않는다. S3-03a 저장 기반 구현·검토 완료이며 03b 제품 연결·개발 검증을 완료했다. 사용자 수동 검사는 대기다.

### 청소 속도 기준

사용자는 **세 도구의 A/B/광택 속도 모두 10배**가 만족스럽다고 확인했다. 반경은 유지한다. S3-00에서 저장값·에디터 메모리값을 구분하며, 선호값의 적용 여부를 추측하지 않는다.

| 도구 | 준비 시 디스크 A / B / 광택 | 사용자 선호 목표 A / B / 광택 | 반경 |
| --- | --- | --- | --- |
| DryCloth | 0.04 / 0.48 / 0.12 | 0.4 / 4.8 / 1.2 | 0.32 |
| SmallBrush | 0.125 / 0.12 / 0 | 1.25 / 1.2 / 0 | 0.18 |
| PolishingCloth | 0.015 / 0.24 / 0.48 | 0.15 / 2.4 / 4.8 | 0.28 |

S3-00 조회에서 세 도구의 에디터 메모리는 선호 목표와 일치하고 모두 Dirty=true, 디스크는 표의 이전 값임을 확인했다. CleaningRoom에도 저장되지 않은 변경이 있어 그대로 보존했다.

S3-01a에서 작업 직전 값을 재조회하고 **목표 절대값으로 한 번만** 반영·저장·회귀 검사한다. 이미 목표값이면 다시10배 하지 않는다. 이후 사용자 조정이 있으면 덮어쓰지 않고 새 기준을 기록한다. 도구 에셋별 저장을 사용하고 관련 없는 Dirty 씬·에셋을 일괄 저장/재로드하지 않는다. 기존 10/12 빌드에는 이 추가10배가 포함됐다고 간주하지 않는다. 마른 천 능력 제한·광택 표현 수정은 이 준비 작업에 섞지 않는다.

## 3. 기존 콘텐츠·입력 기준선

### 문지르기 입력 계약 (2026-10-13 사용자 승인)

아래 계약은 기존 닦기·솔질·연마 도구에 적용한다. 스포이드·스캐너 등 새 도구에 이동 필수를 일괄 적용하지 않으며 Ra에서 별도 입력/효력 조건을 정한다.

- A/B/광택·효과/소리는 포인터가 프레임당 계산한 같은 문지르기 샘플을 읽는다. 여러 소비자의 조회는 샘플을 소모하지 않으며 A/B 소유자는 같은 샘플을 각1회만 적용한다.
- Inspector `minimumRubDistance` 기본0.001 **월드 단위**: 작은 이동을 누적한다. `referenceRubSpeed` 기본0.6 **월드 단위/초**: 기존 도구 초당량을 유지하며, 이동 거리/기준 속도와 실제 이동 프레임 시간 중 작은 값을 적용 예산으로 사용한다. 정지 시간은 예산으로 누적하지 않는다.
- 최초 접촉·재클릭·UI/표면 이탈·포커스·도구/판 교체·MMB/Wheel/F 이후에는 기준점만 잡는다. 유효 연속 드래그만 A/B/광택을 변경하며 A/B 모두 같은 구간을 분할해 예산을 나눈다. 도구 선호 속도값은 재조정하지 않는다.
- 합성 CPU/Scene API 검사와 실제 프레임의 Input System 가상 장치 검사, 물리 마우스/육안 검사를 구분한다. 현재 환경의 가상 장치 실제 프레임 검사는 포커스 상실로 차단되었으며 입력 조건을 우회하지 않았다. 상세 근거/재현은 체크리스트와 [검증 안내](AI/Step3RubbingValidation.md)를 따른다.

- 동전 외형 **2종**, 고정 스테이지 **3개**, 기존 도구 **3종**, 재화 **1종**, 로컬 저장 슬롯 **1개**.
- 두 외형은 같은 검증된 원판 Mesh/Collider 계약을 사용하고 색·문양으로 구분해도 된다. 스테이지별 A 배치/내구도·B 패턴/강도를 구분한다. 실제 산화 반응·새 오염 시뮬레이션은 만들지 않는다.
- 시작 시 마른 천만 보유. 단계별 완료 목표를 낮춰 잠긴 도구 없이도 반드시 완료할 수 있게 한다. 고정 전역 목표를 억지로 통과시키는 우회는 금지한다.

| ID | 구성·목적 | 입장 조건 | 완료 목표 A/B/광택 | 첫 완료 효과 |
| --- | --- | --- | --- | --- |
| stage-01 | 동전 A, 가벼운 A/B; 기본 조작 | 처음부터 열림 | 0.9 / 0.8 / 0 | 재화100, stage-02 및 작은 솔 구매 자격 |
| stage-02 | 동전 B, 큰 먼지와 다른 얼룩 배치 | stage-01 완료 + 작은 솔 보유 | 0.9 / 0.8 / 0 | 재화100, stage-03 및 광택천 구매 자격 |
| stage-03 | 동전 A의 다른 복합 배치; 광택 포함 | stage-02 완료 + 광택천 보유 | 0.9 / 0.8 / 0.7 | 재화100, 준비된 단계 완료 안내·재플레이 |

- 작은 솔 가격60, 광택천 가격100. 시작 재화0. 최소 보상 경로는 `100−60+100−100=40`으로 구매 막힘이 없어야 한다.
- 구매 자격 해금과 소유를 구분한다. 사용 도구는 `소유 도구 ∩ 해당 단계 허용 도구`이며 선택 UI와 실제 사용 검사가 동일한 목록을 따른다.
- 완료한 단계는 재플레이 가능. 프로토타입은 **단계별 첫 완료 보상만** 지급하고 UI에 표시한다. 재플레이는 최고 등급 갱신만 가능하며 반복 보상 경제는 후속이다.
- 기존 범위 제외: 영구 수집·전시, 랜덤 무한 모드, 대규모 콘텐츠, 도구 강화, 클라우드 저장, 다중 슬롯, 청소 도중의 마스크/카메라 상태 저장, 새 메뉴 씬. 새 도구와 상태는 S3-R에서 최소 범위를 확정한 후 별도 승인으로 추가한다.

이름은 제안이며 기존 코드 재사용을 우선한다. 데이터 정의 → 순수 진행/저장 → 씬 연결 순으로 구현한다.

### 단계 전환

- 단계 정의를 입력 차단 상태에서 모두 검증한 뒤 적용한다. 부분 적용 중 청소/완료 검사를 돌리지 않는다. 실패하면 이전 안전 상태/선택 화면에 머물고 오류를 알린다.
- A 배열의 개수·초기 내구도와 Removed 구독을 새 배치에 재설정한다. 현재 `ObjectDirtCleaner`는 Awake에서 배열을 집계하므로 오브젝트만 교체하면 안 된다.
- B/광택 초기 패턴·완료 목표·외형·도구 목록·기본 도구를 먼저 설정한 뒤 새 판 초기화한다. 이전 마스크·연출·부모/Transform·커서·소리·타이머가 남지 않게 한다.
- `RestartRound()`는 현재 완료된 판의 재시작 전용이다. 다음 단계/중도 포기에서는 완료 플래그를 조작해 우회하지 말고 공통 초기화 절차를 명시적으로 분리한다.
- 단계 선택 패널을 여는 동안 진행 타이머/입력이 계속 흐르지 않도록 상태를 정의한다. 청소 중에는 선택 화면 이동 전 포기 확인, 취소 시 기존 판 유지. 포기는 보상을 주지 않고 해당 판만 폐기한다.
- 위 포기는 현재 판을 버리는 교체 절차에 한정한다. 방 안 이동/전시 감상은 현재 작업을 메모리에 유지하며 복귀 시 초기화하지 않는다. 새 동전 생성/교체는 작업대에서 명시적으로 실행한다. 완료마다 전시 이동을 강제하지 않는다.
- 표면·A·입력·완료·표현 참조를 명시적으로 다시 연결한다. 단계 전환마다 중복 싱글턴/구독/마스크/AudioSource가 늘지 않는다.

### 결과·보상·구매

현재 계약: 기존 손상을 미청소/사용자 실수로 평가하지 않는다. 보존 작업·점수·등급·보상은 미정이며 보존 우선 평가를 강제하지 않는다. 아래 등급/보상/구매는 종전 시험안이다. 채택 여부는 Rc 이후 확정하고, 채택한 거래에는 중복 방지와 저장 실패 원칙을 적용한다. 선택 광택 채택 시 청소 완료만으로 결과를 영구 고정하지 않으며 Ra의 최종 보관 규칙을 따른다.

- 결과 등급 기본안: 완료 시 시간≤180초 A, ≤300초 B, 그 외 C. 임시 스테이지 데이터 값으로 노출하고 정확한 경계 검사를 한다. 시간제한·실패·강제 대기는 없다. 저장할 시간은 포커스 제외 게임 타이머이며 실측 목표와 혼동하지 않는다.
- 등급은 결과 시점에 고정한다. 재화는 등급과 무관한 첫 완료 고정100으로 시작한다. 최고 등급만 개선하고 동일 등급이면 짧은 시간을 보존한다.
- 완료 처리의 `재화 + 완료 ID + 최고 결과 + 해금 근거`는 한 거래다. 같은 판 콜백·중복 클릭·재접속으로 재지급되지 않아야 한다.
- 구매는 자격·미소유·잔액·유효 가격을 다시 검사하고 차감과 소유권 추가를 한 거래로 처리한다. 재구매·음수 잔액·잠긴 도구 직접 선택을 막는다.
- 저장 실패 시 거래 성공을 표시하거나 다음 단계로 보내지 않는다. 재시도 시 중복 차감/지급 없이 같은 거래를 처리한다.

## 5. 저장 계약

[Rc 판정](AI/Step3RcDecision.md)에 따라 현재 완성 결과의 최소 저장·복원을 구현한다. 실제 형식·파일/용량 한계·검증 증거는 [S3-03 검증 기록](AI/Step3SaveValidation.md)에 명시한다. 중간 판 저장 제외와 안전 저장/복구 원칙을 유지한다.

저장은 일반 진행(설정·소유 등), 동전 디자인, 초기 생성 시드/규칙 버전, 완성 결과(위치별 오염·광택·채택한 손상)를 구분한다. 현재 진행 DTO만으로 완성 동전 보존을 충족했다고 보고하지 않는다. 현재 Rc 판정에 따라 명시적 보관 확정 시점의 실험 완성 결과를 S3-03에 포함한다. 제작기·공유 구현은 이 저장 단계의 필수가 아니다. 해시는 식별용이며 최종 상태 데이터 자체를 대신하지 않는다.

- `Application.persistentDataPath` 아래 버전 포함 저장소. 완성 결과는 안정 ID·정의 버전·최종 양면 상태를 보존하고 최대16개로 시작한다. 일반 진행은 별도 책임으로 분리하며 실험 도구 접근을 소유권으로 저장하지 않는다. 기존 재화/등급/최고기록 DTO 초안은 이번 요구에서 제외한다. 형식과 압축은 무손실 왕복·용량 측정 후 선택한다.
- 미완료 청소는 종료 시 저장되지 않음을 고지하고 폐기한다. 재실행 시 중간 상태를 복원하지 않으며 새 작업은 작업대에서 시작한다. 완성 동전과 일반 진행은 별도 저장한다. 목표 후 추가 청소도 보관 전에는 미저장 상태이며 종료 콜백에만 저장을 의존하지 않는다.
- 새 진행 사본을 검증→임시 파일 쓰기/닫기→본 파일 교체·이전 유효본 백업→메모리/화면 확정. 본 파일을 먼저 비우지 않는다. 교체 실패면 이전 진행을 유지하며 완료 화면의 미저장 거래 재시도만 허용한다.
- 로드 시 본 파일 우선, 손상됐으면 유효 백업 복구를 알린다. 실패 원본은 보존한다. 둘 다 없을 때만 신규 진행 생성. 둘 다 손상되거나 미래 버전이면 자동 초기화/덮어쓰기를 하지 않고 안내·재시도 상태로 둔다.
- ID 중복·미정의 ID·NaN/무한 시간·양면 배열/수치·불가능한 소유/완료 조합을 검증한다. 재화/등급은 이번 저장 형식에 포함하지 않는다. 호환 규칙 없이 조용히 삭제/정규화하지 않는다. 데이터 ID 개명은 명시적 이전 규칙이 필요하다.
- 사용자 저장으로 테스트하지 않는다. 임시 별도 경로에서 빈 파일·손상·백업·쓰기 실패·중단 시점·미래 버전을 검증한다. 자동 저장 테스트 파일은 Git 제외한다.

## 6. 구현 순서·완료 기준

세부 a/b 단위와 진행은 [체크리스트](AI/Step3ImplementationChecklist.md)에 둔다.

1. **S3-00 준비:** 현재 파일/Unity 기준선, 사용자 튜닝값 차이, 기존 연결점, 이월·범위 계약을 기록. 제품 변경 없음.
2. **S3-01 데이터:** 선호 속도 반영·회귀, 동전/단계/카탈로그와 검증기·시험 콘텐츠 정의.
3. **S3-02 단계 실행:** 안전한 초기화·선택/재도전/다음 단계·동전/오염 교체. 임시 전체 도구 허용은 개발 검사 전용이며 최종 해금 우회 금지.
4. **S3-R 방향 전환:** 대응표·목표 설계 → 승인된 최소 구현 → 사용자 체험 검증. 기존 완료 단계를 재번호하지 않는다.
5. **S3-03 저장 기반:** S3-R에서 확정한 결과/도구 정의로 DTO·검증·안전 저장/로드·오류 처리. 이후 모든 진행 거래가 이 경로를 사용.
6. **S3-04 결과·진행:** 2026-10-19 승인 범위04a의 개발 검증을 완료했다([검증 기록](AI/Step3ResultFinalizationValidation.md)). 제품 로직은 유지하고 검사 코드를 보강했다. 목표 달성 후 추가 청소/도포를 허용하고 보관 확인 시점의 표면·시간을 저장 후보로 고정한다. 파일 재조회 성공 후 보관 완료로 전환하며 확인 취소/확정 전 실패 취소는 작업을 유지한다. 보관 결과의 관찰 전용·새 판과의 독립성을 검증한다. 모달/저장 대기 시간은 작업 시간에서 제외한다. 03b 구현과 증거를 재사용하며 미검증 경계와 확인된 결함만 보완한다. 04b 중복 확정·진행 통합은 후속이며 등급·보상·해금은 보류한다.
7. **S3-05 도구 접근:** 소유/적합성 구분. 상점 채택 시 구매·잔액·저장 실패/재시도 구현, 미채택 시 대체 획득 방식으로 계획 수정.
8. **S3-06 UI 통합:** 단일 게이지·오염 확인·최종 보관·잠금/오류 안내와 작업대 선택 방식. 방 이동과 판 폐기를 구분하고 전시 이동은 선택으로 유지.
9. **S3-07 최종 검증:** 확정한 대표 작업→보관/다음 작업→종료·재실행→저장 대상 복원. 채택한 거래의 중복 없음, Windows 빌드·사용자 검사·이월 상태 보고.

각 단위는 컴파일/Console·데이터/참조·해당 동작 검사·보존 확인 후 인계한다. 금전/저장/전환은 실패 경로를 자동 회귀로 남긴다. 성능/시각/실제 입력을 수치 테스트 통과만으로 인증하지 않는다.

**Step 3 완료:** Rc에서 채택한 청소·도구 반응·완료/보관·저장 범위를 Windows에서 검증한다. 거래를 채택했다면 중복 지급/구매 막힘을 검사한다. 단계3개·구매2회·고급 손상·제작기를 완료 의무로 두지 않는다. 결과 저장을 이월했다면 완성 동전 영구 보관은 아직 미구현임을 명시한다. `Builds/Windows/Step3-<날짜>-<구분>/`에 별도 빌드하며 생성물은 커밋하지 않는다. Step2 이월 품질 검증은 별도 추적한다.
