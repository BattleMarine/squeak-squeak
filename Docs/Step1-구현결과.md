## 구성과 조정값

- 시작 씬은 `Assets/Scenes/CleaningRoom.unity`이며 `SampleScene`은 빌드에서 제외했다. `CleaningController`가 입력·도구 선택·A 청소·진행·완료를 연결하고, `Coin/CoinBody`가 B 오염·광택 표현을 소유한다. Canvas에는 도구 버튼 3개, HUD, 결과 및 재시작 버튼이 연결돼 있다.
- 입력은 Mouse Move=도구 커서, LMB Hold·Drag=청소, MMB Drag=동전 회전, Wheel=줌, F=자세·줌만 복원이다. 커서는 중심점과 현재 도구의 A 접촉 반경 링을 표시하며 UI 위에서는 숨긴다. UI 위·회전 중에는 청소를 차단하는 구조다. 실제 입력 경계 동작은 아직 확인하지 못했다.
- A 제거율은 제거한 고정 오염 수 / 판 시작 오염 수, B 제거율은 `1 - 현재 B / 판 시작 B`로 계산한다. 초기 B가 0이면 B 제거율은 100%다. A ≥90%, B ≥80%, 광택 ≥70%를 모두 충족해야 완료한다. 시간은 첫 실제 오염 변화부터 완료까지 누적하며 포커스를 잃으면 누적하지 않도록 구현했다.
- 도구 반경은 기존 값을 유지했다. 초당 `(A 제거, B 제거, 광택 증가)`는 마른 천 `(0.04, 0.012, 0.003)`, 작은 솔 `(0.125, 0.003, 0)`, 광택천 `(0.015, 0.006, 0.012)`이다. 한 도구가 모든 항목에서 가장 빠르지 않도록 하고 3~5분 목표에 가깝게 조정했으며, 강제 대기 시간은 없다.
- 경사면 A 가시성은 Orthographic 화면 Ray와 0.12 표면 허용 거리를 사용한다. 75°에서 화면에 보이는 A 오염을 막던 기존 판정을 수정했고 135°·180°의 뒷면 오염 차단은 유지했다.

## Windows 빌드

- 최종 검토 조치 반영 결과: `Builds/Windows/Step1-20260929-review/SqueakSqueak.exe` (저장소에서 제외되는 경로)
- `BuildPipeline.BuildPlayer`의 BuildReport: `Succeeded`, 오류 0, 경고 485, 128,671,729바이트. 기존 `com.unity.ai.inference` 셰이더 경고와 같은 계열이다. 도구 래퍼는 경고를 오류 상태로 표시했지만 BuildReport와 실행 파일 생성은 성공했다.
- 빌드 과정에서 Unity가 `ProjectSettings/ProjectSettings.asset`의 `preloadedAssets`에 기존 Input Actions 에셋 참조를 추가했다. 패키지·그래픽 설정은 바꾸지 않았다.
- 플레이어 실행을 Computer Use로 시도했으나 애플리케이션 제어 권한이 거부됐다. 실행·실제 입력 검증을 통과한 것으로 기록하지 않는다.

## 다음 수동 검증 순서

1. 위 실행 파일을 열어 제품명·1280×720 화면의 HUD/도구 버튼 가독성·창 크기 조절 불가를 확인하고, 시작 시 Player 로그의 새 오류를 확인한다.
2. 작은 솔을 선택해 반경 링이 마른 천·광택천과 다른 크기로 바뀌는지 보고, LMB를 누른 채 A 오염을 하나씩 닦는다. 정지 Hold와 연속 Drag를 각각 확인하고 A 5개 제거 및 HUD 변화를 본다. 동전 밖·UI 위·UI 경계 진입/이탈 때 효과와 커서 표시가 멈추는지 확인한다.
3. MMB로 동전을 돌려 경사면과 뒷면을 확인한다. MMB+LMB 동시 입력, Wheel 줌 극값, F 자세·줌 복원 후 청소 진행 보존을 확인한다. 창 포커스를 잃고 돌아온 뒤 손을 떼었을 때 도구가 혼자 작동하지 않아야 한다.
4. 마른 천으로 B를 닦고 광택천으로 마무리해 결과의 청결도·광택도·완료 시간을 확인한다. 첫 유효 청소부터 완료까지 실제 시간을 기록하고, 포커스 이탈 시간이 제외되는지 확인한다. 3~5분 밖이라면 사용 도구·접촉 시간·이동 시간을 적고 수치를 재조정한다.
5. 결과 화면의 `새 청소 시작`을 눌러 초기 도구·오염·광택·HUD·시간·자세·줌을 확인하고 재완료한다. 이 전체 루프를 최소 2회 반복해 이벤트 중복과 UI 잔류가 없는지 확인한다.
